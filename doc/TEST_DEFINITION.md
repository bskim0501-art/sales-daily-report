## 1. 테스트 개요

### 1.1 목적

영업 일일 보고 시스템의 기능적 정확성, 권한 통제, UI 동작, 비기능 요건을 검증하여 운영 배포 전 품질을 확보한다.

### 1.2 테스트 유형

| 유형 | 설명 | 담당 |
|------|------|------|
| 단위 테스트 (Unit) | 개별 함수·모듈 수준 로직 검증 | 개발팀 |
| 통합 테스트 (Integration) | API 엔드포인트 입력/출력 및 DB 연동 검증 | 개발팀 |
| 시스템 테스트 (System) | 전체 기능 흐름 시나리오 검증 | QA팀 |
| 회귀 테스트 (Regression) | 수정 후 기존 기능 영향 여부 확인 | QA팀 |
| UI 테스트 | 화면 조작 및 표시 검증 | QA팀 |
| 비기능 테스트 | 성능, 보안, 접근성 검증 | QA팀 / 보안팀 |

### 1.3 합격 기준 (Exit Criteria)

| 등급 | 기준 |
|------|------|
| 치명 (Critical) | 미결 0건 |
| 주요 (Major) | 미결 0건 |
| 보통 (Minor) | 미결 3건 이하 |
| 경미 (Trivial) | 제한 없음 (차기 스프린트 처리) |

### 1.4 테스트 케이스 ID 규칙

```
TC-{도메인코드}-{번호}

예) TC-AUTH-001, TC-RPT-003, TC-CUST-010
```

| 도메인 코드 | 대상 |
|-------------|------|
| AUTH | 인증 |
| RPT | 보고서 |
| VISIT | 방문 내역 |
| PROB | 과제·상담 |
| PLAN | 내일 할 일 |
| CMT | 댓글 |
| CUST | 고객 마스터 |
| EMP | 영업사원 마스터 |
| AUTH-Z | 권한 통제 |
| UI | 화면 |
| NFR | 비기능 |

## 3. 테스트 대상 및 범위

### 3.1 범위 내 (In Scope)

- 인증 (로그인, 로그아웃, 토큰 갱신)
- 보고서 CRUD 및 상태 전환
- 방문 내역 / 과제·상담 / 내일 할 일 CRUD
- 댓글 CRUD
- 고객·영업사원 마스터 CRUD
- 역할 기반 접근 통제 (SALESPERSON / MANAGER)
- 화면 입력 유효성 및 UX 흐름
- 응답 시간, 동시 접속 성능

### 3.2 범위 외 (Out of Scope)

- 이메일 발송 연동
- 모바일 앱 (웹 전용)
- 외부 ERP 연동
